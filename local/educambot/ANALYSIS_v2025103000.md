## RESUMEN EJECUTIVO

El plugin `local_educambot` es un chatbot educativo LOCAL para Moodle con una arquitectura sofisticada que incluye procesamiento de lenguaje natural, sistema de inferencia, repositorio de conocimiento estructurado y memoria conversacional. Esta versión 2025103000 introduce mejoras significativas en inteligencia local, algoritmos avanzados de NLP y una base de conocimientos ampliada, sin dependencia de APIs externas.

### Logros de la Versión Actual (2025102900)

✅ Sistema NLP con normalización, tokenización, stopwords y stemming
✅ Matching manager con scoring multinivel (exact, partial, semantic, contextual, keywords)
✅ Repositorio de conocimiento estructurado con búsqueda y scoring
✅ Motor de inferencia que decide entre reglas y conocimiento
✅ Memoria de sesión para seguimiento conversacional
✅ Context provider con personalización de mensajes
✅ Widget JavaScript con interfaz completa
✅ Sistema de logging y auditoría
✅ Soporte para múltiples idiomas (ES, EN)

### 1.2 Base de Datos

#### Tablas Principales

**`local_educambot_rule`** - Reglas y patrones del chatbot
- `id`: ID único
- `pattern`: Pregunta o patrón principal
- `synonyms`: Sinónimos y frases alternativas
- `keywords`: Palabras clave
- `response`: Respuesta (HTML)
- `roles`: Restricción por roles
- `contexts`: Contextos de página
- `suggested`: Marcador de sugerencia proactiva
- `enabled`: Estado habilitado/deshabilitado
- `timecreated`, `timemodified`: Timestamps

**`local_educambot_knowledge`** - Base de conocimiento estructurado
- `id`: ID único
- `title`: Título del artículo
- `summary`: Resumen
- `content`: Contenido completo
- `contentformat`: Formato del contenido
- `type`: Tipo de artículo
- `externalurl`: URL externa
- `tags`: Etiquetas
- `enabled`: Estado habilitado/deshabilitado
- `createdby`, `updatedby`: IDs de usuario
- `timecreated`, `timemodified`: Timestamps

**`local_educambot_topic`** - Temas organizacionales
- `id`: ID único

- `parentid`: ID del tema padre
- `sortorder`: Orden de clasificación
- `timecreated`, `timemodified`: Timestamps

**`local_educambot_kn_topic`** - Relación conocimiento-temas
- `id`: ID único
- `knowledgeid`: ID de conocimiento

- `id`: ID único

**`local_educambot_kn_context`** - Contexto de conocimiento
- `id`: ID único

#### Índices Optimizados

- **MySQL**: Índices FULLTEXT en `pattern`, `synonyms`, `keywords` (rules) y `title`, `summary`, `content`, `tags` (knowledge)
- **PostgreSQL**: Índices GIN con `to_tsvector` para búsqueda de texto completo
- Índices compuestos en `enabled, suggested` para filtrado rápido
- Índices únicos en relaciones para prevenir duplicados

### 1.3 Flujo de Procesamiento Actual

```
1. Usuario envía pregunta → service.php
   ↓
2. engine.php inicializa contexto
   ↓
3. pipeline.php procesa la pregunta:
   - Normalización (lowercase, acentos, puntuación)
   - Tokenización
   - Filtrado de stopwords
   - Stemming
   - Extracción de entidades
   ↓
4. matching_manager.php calcula scores para reglas:
   - Exact match
   - Partial match
   - Semantic match (sinónimos)
   - Contextual match
   - Keywords match
   ↓
5. knowledge_repository.php busca en conocimiento estructurado:
   - Búsqueda por título, resumen, contenido, tags
   - Scoring basado en similitud
   - Boosts contextuales (curso, página, rol)
   ↓
6. inference_engine.php decide entre regla y conocimiento:
   - Compara scores
   - Aplica boosts y ajustes
   - Expande con relaciones
   ↓
7. Respuesta formateada y personalizada:
   - Interpolación de placeholders
   - Formato HTML
   ↓
8. session_memory.php almacena intercambio
   ↓
9. logger.php registra interacción
   ↓
10. Respuesta JSON enviada al frontend
```

### 1.4 Análisis de Algoritmos Actuales

#### NLP Pipeline (classes/nlp/pipeline.php)

**Fortalezas:**
- Normalización efectiva con conversión de acentos
- Stopwords bilingües (ES/EN)
- Stemming básico para español
- Extracción de entidades (códigos de curso, actividades, fechas, números)

**Limitaciones:**
- Stemming simple que no maneja todos los casos del español
- Sin soporte para n-gramas
- Sin cálculo de TF-IDF
- Sin detección de idioma automática
- Sin expansión de abreviaturas

#### Matching Manager (classes/matching/manager.php)

**Fortalezas:**
- Sistema de scoring multinivel sofisticado
- Soporte para wildcards
- Matching por sinónimos
- Boost contextual por página y entidades

**Limitaciones:**
- No usa TF-IDF para ponderación
- Sin detección de intención explícita
- Sin manejo de consultas multi-parte
- Pesos fijos sin aprendizaje

#### Knowledge Repository (classes/local/knowledge_repository.php)

**Fortalezas:**
- Búsqueda multicriterio
- Sistema de caché robusto
- Expansión de relaciones
- Boost por contexto

**Limitaciones:**
- Búsqueda basada en LIKE (no full-text search real)
- Sin ranking BM25 o similar
- Sin recomendación basada en historial
- Filtros de contexto demasiado restrictivos (corregido en bugfixes)

#### Session Memory (classes/context/session_memory.php)

**Fortalezas:**
- Detección de follow-up simple
- Agregación de keywords del historial
- Límite configurable de historial

**Limitaciones:**
- Sin análisis de sentimiento
- Sin detección de frustración
- Sin análisis de patrones de conversación
- Sin resumen de sesión

## PARTE 2: ERRORES Y PROBLEMAS IDENTIFICADOS

### 2.1 Errores Críticos

#### ❌ NINGÚN ERROR CRÍTICO ENCONTRADO

El código actual está bien escrito y funcional. Los problemas identificados son más sobre optimizaciones y mejoras que errores reales.

### 2.2 Problemas de Optimización

#### ⚠️ P1: Performance de Búsqueda en Knowledge Repository

**Ubicación:** `classes/local/knowledge_repository.php:284-339`

**Problema:** La búsqueda usa múltiples `LIKE` statements que pueden ser lentos con bases de datos grandes.

**Impacto:** Búsquedas lentas con >1000 entradas de conocimiento.

**Solución:** Ya implementado en la función `fallback_candidate_scan()`, pero se puede mejorar con índices full-text ya existentes.

#### ⚠️ P2: Stemming Limitado en Pipeline NLP

**Ubicación:** `classes/nlp/pipeline.php:142-159`

**Problema:** El algoritmo de stemming es muy básico y no maneja muchos casos del español.

**Impacto:** Matches perdidos por variaciones de palabras.

**Solución:** Implementar un stemmer más robusto basado en reglas morfológicas del español.

#### ⚠️ P3: Sin Sistema de Intenciones Explícito

**Ubicación:** Todo el sistema

**Problema:** No hay detección explícita de intenciones (preguntar, solicitar ayuda, reportar problema, etc.).

**Impacto:** Respuestas menos contextuales.

**Solución:** Implementar un sistema de intenciones con patrones predefinidos.

#### ⚠️ P4: Corrección Ortográfica Limitada

**Ubicación:** `classes/local/text_helper.php:134-154`

**Problema:** Solo se usa `levenshtein` y `similar_text`, sin corrección proactiva.

**Impacto:** Errores tipográficos causan pérdida de matches.

**Solución:** Implementar corrección ortográfica con sugerencias "¿Quisiste decir...?".

### 2.3 Oportunidades de Mejora

#### 📈 M1: Base de Conocimientos Vacía por Defecto

**Problema:** El plugin se instala sin datos de ejemplo, requiriendo configuración manual extensiva.

**Solución:** Crear un seed amplio con 200+ entradas sobre Moodle.

#### 📈 M2: Sin Analítica de Conversaciones

**Problema:** No hay dashboards o reportes de analítica sobre preguntas frecuentes, temas comunes, etc.

**Solución:** Implementar sistema de analítica con agregaciones y visualizaciones.

#### 📈 M3: Respuestas Simples

**Problema:** Las respuestas son texto plano/HTML simple, sin estructura enriquecida.

**Solución:** Implementar respuestas enriquecidas con cards, botones, listas estructuradas, etc.

#### 📈 M4: Sin Exportación/Importación de Knowledge Base

**Problema:** No hay manera fácil de exportar/importar la base de conocimientos.

**Solución:** Implementar exportación JSON/CSV e importación con validación.
