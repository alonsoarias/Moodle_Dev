2. Generacion de Firma

2.1 Firma para Envio (Payment Form)

La firma asegura la integridad de los datos enviados al formulario de pago.

Formula:

// Concatenar en orden:
$signatureString = $apiKey . '~' . $merchantId . '~' . $referenceCode . '~' . $amount . '~' . $currency;

// Aplicar MD5 (o SHA256):
$signature = md5($signatureString);

// Ejemplo:
$apiKey = "4Vj8eK4rloUd272L48hsrarnUA";
$merchantId = "508029";
$referenceCode = "TestPayU";
$amount = 20000;
$currency = "COP";

$signatureString = "4Vj8eK4rloUd272L48hsrarnUA~508029~TestPayU~20000~COP";
$signature = md5($signatureString);
// Resultado: "7ee7cf808ce6a39b17481c54f2c57acc"

Orden de Concatenacion (Envio)

apiKey ~ merchantId ~ referenceCode ~ amount ~ currency

2.2 Firma para Validacion (Confirmation/Response)

Para validar la respuesta de PayU, se usa una formula diferente que incluye el estado.

Formula:

// Concatenar en orden:
$signatureString = $apiKey . '~' . $merchantId . '~' . $referenceCode . '~' . $value . '~' . $currency . '~' . $statePol;

// Aplicar MD5 (o SHA256):
$signature = md5($signatureString);

Regla de Formateo del Valor

El valor debe formatearse segun estas reglas:

  • Si el segundo decimal es 0: usar 1 decimal (150.00 → 150.0)
  • Si el segundo decimal no es 0: usar 2 decimales (150.25 → 150.25)

Implementacion PHP:

/**
 * Formatea el valor segun reglas de PayU para firma.
 */
public function format_value_for_signature(float $value): string {
    $rounded = round($value, 2);
    $decimals = $rounded - floor($rounded);

    // Verificar si el segundo decimal es cero
    $secondDecimal = (int)(($decimals * 100) % 10);

    if ($secondDecimal == 0) {
        return number_format($rounded, 1, '.', '');
    }
    return number_format($rounded, 2, '.', '');
}

/**
 * Genera firma para validacion de respuesta.
 */
public function generate_response_signature(
    string $referenceCode,
    float $value,
    string $currency,
    int $statePol
): string {
    $formattedValue = $this->format_value_for_signature($value);

    $signatureString = sprintf(
        '%s~%s~%s~%s~%s~%s',
        $this->apiKey,
        $this->merchantId,
        $referenceCode,
        $formattedValue,
        $currency,
        $statePol
    );

    return md5($signatureString);
}

3. Estados de Transaccion

3.1 Codigos de Estado (state_pol / transactionState)

Codigo Estado Descripcion Accion Recomendada
4 APPROVED Transaccion aprobada exitosamente Entregar producto/servicio
5 EXPIRED Transaccion expirada por timeout Permitir reintento
6 DECLINED Transaccion rechazada por el banco Notificar al usuario
7 PENDING Transaccion pendiente de confirmacion Esperar confirmacion (PSE, efectivo)
104 ERROR Error en el procesamiento Revisar logs, contactar soporte

3.2 Flujo de Estados

INICIO (Usuario envia formulario) | v [WebCheckout PayU] -----> Usuario selecciona metodo y paga | +-----------> [4 - APPROVED] ---> Entregar orden | +-----------> [6 - DECLINED] ---> Notificar rechazo | +-----------> [7 - PENDING] ----> Esperar confirmacion (PSE/efectivo) | | | +---> [4 - APPROVED] via Confirmation | | | +---> [5 - EXPIRED] (timeout) | +-----------> [104 - ERROR] ---> Revisar logs

4. Pagina de Confirmacion (Server-to-Server)

4.1 Descripcion

La pagina de confirmacion recibe notificaciones POST de PayU cuando cambia el estado de una transaccion. Es invisible para el usuario y se usa para actualizar inventarios/ordenes.

Requisitos de la URL de Confirmacion

  • Debe ser una URL publica con IP valida
  • No debe requerir autenticacion
  • Debe aceptar peticiones POST
  • Content-Type: x-www-form-urlencoded
  • Si usa HTTPS, debe tener certificado SSL valido

4.2 Parametros Recibidos (POST)

4.3 Implementacion PHP (callback.php)

// 1. Obtener parametros POST
$merchantId = $_POST['merchant_id'] ?? '';
$referenceSale = $_POST['reference_sale'] ?? '';
$value = $_POST['value'] ?? 0;
$currency = $_POST['currency'] ?? '';
$statePol = (int)($_POST['state_pol'] ?? 0);
$receivedSign = $_POST['sign'] ?? '';
$transactionId = $_POST['transaction_id'] ?? '';

// 2. Validar firma
$expectedSign = $payuHelper->generate_response_signature(
    $referenceSale,
    (float)$value,
    $currency,
    $statePol
);

if (!hash_equals(strtoupper($expectedSign), strtoupper($receivedSign))) {
    http_response_code(400);
    die('Invalid signature');
}

// 3. Procesar segun estado
if ($statePol === 4) { // APPROVED
    // Entregar orden
    $payuHelper->deliver_order($component, $paymentarea, $itemid, $userid, $value, $currency);
    $payuHelper->mark_as_delivered($referenceSale);
} else if ($statePol === 7) { // PENDING
    // Solo actualizar estado, esperar confirmacion final
    $payuHelper->update_transaction($referenceSale, 'PENDING');
} else {
    // Rechazado o error
    $payuHelper->update_transaction($referenceSale, 'DECLINED');
}

echo 'OK';

4.4 Manejo de Reintentos

Multiples Notificaciones

PayU puede enviar multiples notificaciones para la misma transaccion (reintentos del usuario). Cada notificacion tiene el mismo reference_sale pero diferente transaction_id. Tu sistema debe manejar la idempotencia.

5.4 Diferencia entre Confirmation y Response

Confirmation Page

  • Metodo: POST
  • Origen: Servidor PayU
  • Proposito: Actualizar BD
  • Parametro estado: state_pol
  • Confiable: Si (server-to-server)
  • Visible: No (invisible al usuario)

Response Page

  • Metodo: GET
  • Origen: Redireccion navegador
  • Proposito: Mostrar resultado
  • Parametro estado: transactionState
  • Confiable: Parcial (puede manipularse)
  • Visible: Si (usuario lo ve)

Importante

Nunca uses solo la Response Page para entregar ordenes. Siempre verifica el estado real via Confirmation Page o consulta a la API.

6.2 Flujos por Tipo de Pago

Tarjeta de Credito (Instantaneo)

Usuario → WebCheckout → Ingresa datos tarjeta → Banco procesa | Confirmation (state_pol=4) ←---+ Response (transactionState=4) ←+

PSE (Transferencia Bancaria)

Usuario → WebCheckout → Selecciona banco PSE → Redirige a banco | Usuario paga en portal del banco | Confirmation (state_pol=7) PENDING ←-+ | 15-30 minutos | Confirmation (state_pol=4) APPROVED

Efectivo (Efecty, Baloto)

Usuario → WebCheckout → Genera referencia de pago | Usuario va a punto fisico (Efecty/Baloto) | Paga en efectivo | Confirmation (state_pol=7) PENDING | Hasta 24-48 horas | Confirmation (state_pol=4) APPROVED

6.3 Manejo de Pagos Pendientes

Recomendacion

Para pagos PSE y efectivo, implementa una tarea programada (cron) que consulte el estado de transacciones pendientes cada 5-10 minutos usando la API de consultas.
