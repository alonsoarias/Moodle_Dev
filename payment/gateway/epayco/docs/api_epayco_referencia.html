1. Configuracion de checkout.js

1.1 Inclusion del Script

ePayco proporciona una biblioteca JavaScript para integrar el checkout en tu sitio:

<!-- Incluir en el <head> o antes de usar -->
<script src="https://checkout.epayco.co/checkout.js"></script>

1.2 Configuracion del Handler

Inicializa el handler con tu llave publica:

// Configurar el handler de ePayco
var handler = ePayco.checkout.configure({
    key: 'TU_PUBLIC_KEY',      // Llave publica del comercio
    test: true                    // true = modo prueba, false = produccion
});

1.3 Credenciales de ePayco

Credencial Descripcion Uso
p_cust_id_cliente ID unico del comercio Validacion de firma
p_key Llave secreta del comercio Validacion de firma (NO exponer al cliente)
public_key Llave publica Inicializar checkout.js
private_key Llave privada API Llamadas API server-side

Seguridad

p_key y private_key son secretas. Nunca las expongas en el frontend. Solo usa public_key en JavaScript.

2.2 Parametro external: OnPage vs Standard

OnPage (external: "false")

  • Modal embebido en tu sitio
  • Usuario no sale de la pagina
  • Experiencia mas fluida
  • Recomendado para Moodle

Standard (external: "true")

  • Redirige a pagina de ePayco
  • Usuario sale del sitio
  • Mas metodos de pago disponibles
  • Retorna via URL response

3. Codigos de Respuesta (x_cod_response)

3.1 Codigos Principales

Codigo Estado Descripcion Accion
1 Aceptada Transaccion aprobada exitosamente Entregar producto/servicio
2 Rechazada Transaccion rechazada por banco/procesador Notificar rechazo, permitir reintento
3 Pendiente Esperando confirmacion (PSE, efectivo, Nequi) Esperar callback de confirmacion
4 Fallida Error en el flujo de la transaccion Revisar logs, permitir reintento

3.2 Codigos Extendidos

Codigo Estado Descripcion
6 Reversada Transaccion reversada/reembolsada al cliente
7 Retenida Retenida para revision de fraude
8 Iniciada Transaccion iniciada, pendiente de completar
9 Expirada/Caducada Tiempo de pago expirado (efectivo/SafetyPay)
10 Abandonada Usuario abandono el proceso de pago
11 Cancelada Transaccion cancelada por usuario o sistema
12 Antifraude Rechazada por sistema antifraude

3.3 Flujo de Estados

INICIADA (8) | v [CHECKOUT] ──> Usuario completa pago | +──────────> ACEPTADA (1) ───────> Entregar orden | +──────────> PENDIENTE (3) ──────> Esperar confirmacion | | | +──> ACEPTADA (1) | +──> RECHAZADA (2) | +──> EXPIRADA (9) | +──────────> RECHAZADA (2) ──────> Notificar rechazo | +──────────> FALLIDA (4) ────────> Error tecnico | +──────────> ABANDONADA (10) ────> Usuario cerro checkout

4. Validacion de Firma (x_signature)

4.1 Algoritmo de Firma

Formula de la Firma

La firma se genera concatenando valores con el caracter ^ y aplicando SHA256:

signature = SHA256(p_cust_id_cliente ^ p_key ^ x_ref_payco ^ x_transaction_id ^ x_amount ^ x_currency_code)

4.2 Implementacion en PHP

/**
 * Calcular firma para validacion de transaccion.
 *
 * @param string $refpayco     Referencia ePayco (x_ref_payco)
 * @param string $transactionid ID de transaccion (x_transaction_id)
 * @param float  $amount       Monto (x_amount)
 * @param string $currency     Moneda (x_currency_code)
 */
public function calculate_signature(
    string $refpayco,
    string $transactionid,
    float $amount,
    string $currency
): string {
    $signaturestring = sprintf(
        '%s^%s^%s^%s^%s^%s',
        $this->pcustidcliente,  // p_cust_id_cliente
        $this->pkey,            // p_key
        $refpayco,              // x_ref_payco
        $transactionid,         // x_transaction_id
        $amount,                // x_amount
        $currency               // x_currency_code
    );

    return hash('sha256', $signaturestring);
}

4.3 Ejemplo de Calculo

// Datos recibidos en callback
$x_ref_payco = "12345";
$x_transaction_id = "67890";
$x_amount = "50000";
$x_currency_code = "COP";
$x_signature = "abc123...";  // Firma recibida

// Credenciales del comercio
$p_cust_id_cliente = "123456";
$p_key = "a1b2c3d4e5f6";

// Construir string de firma
$signature_string = "123456^a1b2c3d4e5f6^12345^67890^50000^COP";

// Calcular hash
$calculated = hash('sha256', $signature_string);

// Comparar (usar hash_equals para evitar timing attacks)
if (hash_equals($calculated, $x_signature)) {
    // Firma valida - procesar transaccion
} else {
    // Firma invalida - rechazar
}

4.4 Verificacion en Callback

public function verify_signature(
    string $refpayco,
    string $transactionid,
    float $amount,
    string $currency,
    string $receivedsignature
): bool {
    $calculated = $this->calculate_signature(
        $refpayco,
        $transactionid,
        $amount,
        $currency
    );

    // Comparacion segura (case-insensitive)
    return hash_equals(
        strtolower($calculated),
        strtolower($receivedsignature)
    );
}

Importante

Siempre valida la firma ANTES de procesar cualquier transaccion. Rechaza callbacks con firma invalida para prevenir fraudes.

5. URLs de Confirmacion vs Respuesta

5.1 Diferencias Clave

URL de Confirmacion

  • Tipo: Server-to-Server (S2S)
  • Metodo: POST (configurable)
  • Proposito: Procesar pago
  • Cuando: Cambio de estado
  • Usuario: NO presente
  • Respuesta: HTTP 200 OK
  • Reintentos: Si, automaticos

URL de Respuesta

  • Tipo: Redireccion navegador
  • Metodo: GET
  • Proposito: Mostrar resultado
  • Cuando: Fin del checkout
  • Usuario: SI presente
  • Respuesta: Pagina HTML
  • Reintentos: No

5.2 Flujo de Callbacks

Usuario inicia pago | v [Checkout ePayco] ──> Usuario completa formulario | +──────────────────────────────────────────+ | | v v [URL Confirmacion] [URL Respuesta] (POST server-to-server) (GET navegador) | | v v confirmation.php response.php - Valida firma - Consulta API - Procesa pago - Muestra resultado - Entrega orden - Redirige usuario - Retorna 200 OK

5.3 URL de Confirmacion (confirmation.php)

// Archivo: confirmation.php
// No requiere login - es llamado por servidores ePayco

// 1. Recibir parametros
$refpayco = $_REQUEST['x_ref_payco'];
$transactionid = $_REQUEST['x_transaction_id'];
$amount = $_REQUEST['x_amount'];
$currency = $_REQUEST['x_currency_code'];
$signature = $_REQUEST['x_signature'];
$codresponse = $_REQUEST['x_cod_response'];

// 2. Validar firma
if (!$helper->verify_signature($refpayco, $transactionid, $amount, $currency, $signature)) {
    http_response_code(400);
    die('Invalid signature');
}

// 3. Procesar segun estado
if ($codresponse == 1) {
    // Entregar orden
    helper::deliver_order(...);
}

// 4. Responder OK
http_response_code(200);
echo 'OK';

5.4 URL de Respuesta (response.php)

// Archivo: response.php
// Requiere login - usuario presente

require_login();

// 1. Obtener referencia
$refpayco = $_GET['ref_payco'];

// 2. Consultar API de ePayco para obtener detalles
$apiurl = 'https://secure.epayco.co/validation/v1/reference/' . $refpayco;
$response = file_get_contents($apiurl);
$data = json_decode($response, true);

// 3. Mostrar resultado al usuario
$txdata = $data['data'];
$codresponse = $txdata['x_cod_response'];

if ($codresponse == 1) {
    echo 'Pago aprobado!';
} else if ($codresponse == 3) {
    echo 'Pago pendiente...';
} else {
    echo 'Pago rechazado';
}

Buenas Practicas

  • La confirmacion es donde debes entregar el curso/producto
  • La respuesta solo muestra informacion al usuario
  • Siempre valida la firma en la confirmacion
  • En respuesta, consulta la API para obtener datos frescos

7. Manejo de Pagos Pendientes (PSE, Efectivo)

7.1 Metodos con Confirmacion Asincrona

Metodo Tiempo Confirmacion Estado Inicial Notas
PSE 5-20 minutos PENDING (3) Usuario redirigido al banco
Efecty Hasta 24-72 horas PENDING (3) Usuario paga en punto fisico
Baloto Hasta 24-72 horas PENDING (3) Usuario paga en punto fisico
SafetyPay Hasta 72 horas PENDING (3) Puede expirar (codigo 9)
Nequi 1-5 minutos PENDING (3) Push notification al usuario
Daviplata 1-5 minutos PENDING (3) OTP requerido

7.2 Flujo de Pago Pendiente

1. Usuario selecciona PSE/Efectivo | v 2. ePayco retorna x_cod_response = 3 (PENDING) | v 3. confirmation.php recibe callback con PENDING | +──> Guardar transaccion en BD con status PENDING +──> Enviar email al usuario "Pago pendiente" +──> NO entregar orden todavia | v 4. Usuario completa pago (banco/punto fisico) | v 5. ePayco envia NUEVO callback a confirmation.php | +──> x_cod_response = 1 (APPROVED) +──> Validar firma +──> Actualizar status en BD +──> Entregar orden (inscribir curso) +──> Enviar email "Pago aprobado"

7.3 Implementacion en Confirmacion

// En confirmation.php

$codresponse = (int) $_REQUEST['x_cod_response'];

switch ($codresponse) {
    case 1: // ACEPTADA
        // Validar monto
        if ($amount != $expected_amount) {
            http_response_code(400);
            die('Amount mismatch');
        }

        // Entregar orden
        $paymentid = helper::save_payment(...);
        helper::deliver_order($component, $paymentarea, $itemid, $paymentid, $userid);

        // Actualizar BD
        $helper->update_transaction($id, ['status' => 'APPROVED']);

        // Notificar usuario
        $helper->send_notification_email($user, $config, 'completed', [...]);
        break;

    case 3: // PENDIENTE
        // Guardar como pendiente
        $helper->update_transaction($id, ['status' => 'PENDING']);

        // Notificar que esta pendiente
        $helper->send_notification_email($user, $config, 'pending', [...]);

        // NO entregar orden - esperar siguiente callback
        break;

    case 2: // RECHAZADA
    case 4: // FALLIDA
    case 9: // EXPIRADA
    default:
        // Actualizar como fallida
        $helper->update_transaction($id, ['status' => 'FAILED']);
        break;
}

http_response_code(200);
echo 'OK';

7.4 Consulta Manual de Transacciones Pendientes

Para casos donde el callback no llega, puedes consultar la API:

// Consultar estado de transaccion por ref_payco
$apiurl = 'https://secure.epayco.co/validation/v1/reference/' . $refpayco;

$ch = curl_init($apiurl);
curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);
curl_setopt($ch, CURLOPT_HTTPHEADER, ['Content-Type: application/json']);

$response = curl_exec($ch);
$data = json_decode($response, true);

if ($data['success']) {
    $txdata = $data['data'];
    $codresponse = $txdata['x_cod_response'];

    // Procesar segun estado actual
}

Importante: Pagos Efectivo

Los pagos en efectivo (Efecty, Baloto) pueden tomar hasta 72 horas en confirmarse. El callback de confirmacion se enviara automaticamente cuando el usuario pague en el punto fisico.
