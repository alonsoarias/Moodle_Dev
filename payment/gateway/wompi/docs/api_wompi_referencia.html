2. Estados de Transaccion

2.1 Estados Principales

Estado Descripcion Accion Recomendada Final?
PENDING Transaccion iniciada, esperando confirmacion del banco/usuario Esperar webhook o polling No
APPROVED Pago aprobado exitosamente Entregar producto/servicio Si
DECLINED Pago rechazado por el banco o procesador Notificar al usuario, permitir reintento Si
ERROR Error en el procesamiento de la transaccion Revisar logs, contactar soporte si persiste Si
VOIDED Transaccion anulada/cancelada Ninguna accion requerida Si

2.2 Flujo de Estados

INICIO | v [PENDING] -----> Usuario completa pago | +-----------> [APPROVED] ---> Entregar orden | +-----------> [DECLINED] ---> Notificar rechazo | +-----------> [ERROR] ------> Revisar logs | +-----------> [VOIDED] -----> Transaccion cancelada

2.3 Estado Interno del Plugin (Moodle)

Estado BD Descripcion Tabla
PENDING Transaccion creada, esperando respuesta de Wompi paygw_wompi_transactions
APPROVED Wompi confirmo aprobacion, pendiente entregar paygw_wompi_transactions
DELIVERED Orden entregada, usuario inscrito al curso paygw_wompi_transactions
DECLINED Pago rechazado paygw_wompi_transactions

3. Validacion de Firma de Integridad

3.1 Firma para Widget Checkout (signature:integrity)

La firma de integridad asegura que los datos de la transaccion no han sido alterados.

Algoritmo:

// Concatenar en orden:
$concatenated = $reference . $amount_in_cents . $currency . $integrity_key;

// Aplicar SHA256:
$signature = hash('sha256', $concatenated);

// Ejemplo:
$reference = "orden_12345";
$amount_in_cents = 5000000;  // $50,000 COP
$currency = "COP";
$integrity_key = "test_integrity_xxxxxxxxxx";

$concatenated = "orden_123455000000COPtest_integrity_xxxxxxxxxx";
$signature = hash('sha256', $concatenated);
// Resultado: "a1b2c3d4e5f6789..."

Orden de Concatenacion

reference + amount_in_cents + currency + integrity_key

3.2 Llaves de Seguridad

Llave Prefijo Sandbox Prefijo Produccion Uso
Publica pub_test_ pub_prod_ Iniciar Widget, consultar merchant
Privada prv_test_ prv_prod_ API requests, crear transacciones
Integridad test_integrity_ prod_integrity_ Generar firma de transaccion
Eventos test_events_ prod_events_ Verificar firma de webhooks

3.3 Implementacion en PHP (wompi_helper.php)

/**
 * Generate the integrity signature for a transaction.
 * Formula: SHA256(reference + amount_in_cents + currency + integrity_key)
 */
public function generate_integrity_signature(
    string $reference,
    int $amountincents,
    string $currency = 'COP'
): string {
    $concatenated = $reference . $amountincents . $currency . $this->integritykey;
    return hash('sha256', $concatenated);
}

4.3 Verificacion de Firma del Webhook

/**
 * Algoritmo de verificacion:
 * 1. Extraer propiedades indicadas en signature.properties
 * 2. Concatenar valores en orden
 * 3. Agregar timestamp + events_key
 * 4. Aplicar SHA256 y comparar con checksum
 */

public function verify_webhook_signature(array $eventdata, string $signature): bool {
    // 1. Obtener propiedades a concatenar
    $properties = $eventdata['signature']['properties'] ?? [];
    $timestamp = $eventdata['timestamp'] ?? '';

    // 2. Concatenar valores
    $signaturestring = '';
    foreach ($properties as $property) {
        $value = $this->get_nested_value($eventdata, $property);
        $signaturestring .= $value;
    }

    // 3. Agregar timestamp y events_key
    $signaturestring .= $timestamp . $this->eventskey;

    // 4. Calcular y comparar
    $calculatedsignature = hash('sha256', $signaturestring);

    return hash_equals($calculatedsignature, $signature);
}

Ejemplo de concatenacion:

// Properties: ["data.transaction.id", "data.transaction.status", "data.transaction.amount_in_cents"]
// Values:     "01-1699999999-12345" + "APPROVED" + "5000000"
// Timestamp:  1705315935
// Events Key: prod_events_xxxxxxxxxx

$concatenated = "01-1699999999-12345APPROVED50000001705315935prod_events_xxxxxxxxxx";
$checksum = hash('sha256', $concatenated);

4.4 Politica de Reintentos

Reintento Tiempo desde evento Condicion
1 30 minutos HTTP != 200
2 3 horas HTTP != 200

Respuesta Requerida

El webhook DEBE responder con HTTP 200. El contenido del body es ignorado. Cualquier otro codigo causara reintentos.

5.2 Flujos por Metodo de Pago

Tarjeta (CARD)

Usuario → Widget Wompi → Tokenizar tarjeta → POST /transactions → APPROVED/DECLINED (instantaneo)

Nequi

Usuario → Widget → Ingresa celular → POST /transactions → PENDING | Usuario ← Push notification Nequi ← Espera aprobacion | | | v v Aprueba en app ────────────────────────────────────> Webhook → APPROVED

PSE

Usuario → Widget → Selecciona banco → POST /transactions → PENDING | Redirige a banco ←────+ | v Usuario paga en banco | v Webhook → APPROVED

6. Widget Checkout vs API Directa

6.1 Comparacion

Widget Checkout

  • Integracion: JavaScript embebido
  • Complejidad: Baja
  • PCI Compliance: Wompi maneja todo
  • Personalizacion: Limitada
  • Seguridad: Firma de integridad
  • Metodos: Todos soportados
  • Ideal para: Mayoría de comercios

API Directa

  • Integracion: REST API server-side
  • Complejidad: Alta
  • PCI Compliance: Comercio responsable
  • Personalizacion: Total
  • Seguridad: Bearer token + firma
  • Metodos: Todos soportados
  • Ideal para: Flujos personalizados

6.2 Widget Checkout - Implementacion

<!-- 1. Incluir script -->
<script src="https://checkout.wompi.co/widget.js"></script>

<!-- 2. Inicializar widget -->
<script>

6.4 Recomendacion para Moodle

Widget Checkout Recomendado

Para el plugin de Moodle, se recomienda usar el Widget Checkout porque:

  • Menor complejidad de integracion
  • Wompi maneja la seguridad PCI DSS
  • Soporta todos los metodos de pago en una sola interfaz
  • Mantenimiento minimo cuando Wompi actualiza su UI
